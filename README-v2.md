# Jordan James portfolio (v2)

(In the JJ-Portfolio- repo the `site/` folder is `docs/`.)

A static site with no build step: plain HTML, CSS, and JavaScript modules. It is a black and pink portfolio with a CD jewel case menu.

## Run it locally

ES modules do not load from `file://`, so use a tiny server:

```bash
cd site
python3 -m http.server 8000
# open http://localhost:8000/
```

## Structure

```
site/
  index.html          the page shell (nav, hero, work, about, contact)
  css/styles.css      all styles; colors are CSS variables at the top (--pink, --black, --panel)
  js/data.js          ALL content: projects, media map, Steam games, certifications
  js/main.js          behavior: CD menu, dropdowns, hash routes, pages, culture log
  assets/media/       images (.webp), videos (.mp4) and video posters
  404.html            not-found page
  certs.html ...      small redirects so old links keep working
tests/audit.py        automated checks (see below)
tools/optimize.sh     compress new images and videos
migrate.sh            puts this site into the old repo (see MIGRATION.md)
```

## How things work

- Pages are hash routes: `#/matter-monsters`, `#/certifications`, `#/resume`, `#/intern-blog`, `#/culture-log`.
  Project pages are built from `P` in `js/data.js`. The other pages are functions in `js/main.js` (`pageCerts`, `pageResume`, `pageBlog`, `pageLog`).
- Hash routes work on GitHub Pages without any server setup.
- The hero disc order, tiles, Work menu and next/previous links all follow the order of `P`. Keep it newest first.

## Common edits

| Task | Where |
|---|---|
| Add or edit a project | `P` in `js/data.js` (set `date`, `kind`, `blurb`, `tools`, `gallery`, `links`) |
| Add images or video | run `tools/optimize.sh`, then add an entry to `MEDIA` in `js/data.js` |
| Add a game to the log | `STEAM` in `js/data.js`, or `LOG` in `js/main.js` for movies, TV, and other games |
| Add or re-rate a watched movie or show | `WATCH` in `js/data.js` (move the title between rating lists; `~` prefix = TV) |
| Add a certification | `CERTS` in `js/data.js` |
| Update the music section | `MUSIC` in `js/data.js` (see the comment above it for the format) |
| Change colors | variables at the top of `css/styles.css` |
| Edit the resume | `pageResume` in `js/main.js` |

## Culture Log

The nav item opens a **highlights** page (most played game, top artist, newest movie and show, most played song). The dropdown opens full pages for Music, Games, Movies and TV shows, each with a chart and the complete list. Routes: `#/culture-log`, `#/culture/music`, `#/culture/games`, `#/culture/movies`, `#/culture/tv`.

**Cover art.** Games show Steam artwork for the titles listed in `STEAMAPP` (`js/main.js`). Everything else uses `window.COVERS` from `js/covers.js`, which is generated by:

```bash
TMDB_KEY=your_free_key node tools/fetch-covers.mjs --limit=10   # try 10 first, then check site/assets/covers/
TMDB_KEY=your_free_key node tools/fetch-covers.mjs              # then everything
```

Movies and TV come from TMDB, games from Steam, albums and songs from the iTunes Search API. Anything without a cover keeps a letter tile. Console-only games are skipped.

## Mareep

A small pixel-art Mareep sits next to the name in the portfolio nav and opens the special site. The same Mareep sits in the top-left corner of the special site and goes back to the portfolio. It bobs, leans, wags its tail and blinks; it hops on hover and throws sparks on click. The component is `site/special/mareep.js` (it is also copied into `site/js/main.js` for the portfolio). Options: `scale` (0.8 = 80% of the original 44 x 41), `rim` (light edge for dark backgrounds). With reduced motion it stays still.

## The special site (`site/special/`)

A separate, unlisted page with its own look. It is not linked from the portfolio and carries `noindex`. Visit `/special/`.

**Flow:** a bare cream login with a blinking horizontal cursor, then four questions ("Our B-day", "Our First Child", "and the second one...?", "My Original Child"; a hint after 2 wrong tries, then lockouts of 7 seconds, 11 seconds, 7 and so on, every 2 more wrong tries), the typewriter quote intro from Journal-101 (with its own quotes), a slideshow with arrows and morphing dots, a typed "There's More...", a rapid-fire montage of your own photos, an old-TV switch-off, then 16 baby-blue folders that fly in, bounce and settle into a 4 x 4 grid, with sparkles, a ringed planet (pastel orange with a pastel blue ring) and an earth-like planet drifting in behind them. Each folder opens a bubble sized for its media. A Back button returns to the slideshow, and going forward again skips the typing, montage and folder animation.

**Editing it.** Open `/special/`, click the small pencil in the bottom-left corner of the first password page, and type the editor password. The editor lets you change the slides (photos, videos, text, captions, dates, background and text colour), the intro quotes and their speed, the photo barrage (what pops in, how many, how fast, and the vertical ending video that always plays to the end), the folders (how many, titles shown inside, long text, photos and videos with captions, messages and dates), the books (covers and page photos, which are straightened and cleaned like a scan), and the questions (prompts, hints, how many, and their answers, which need the current answer to change). Use **Preview** to see it for real, then **Publish** to commit it to the site with your GitHub token (saved only on your device). Until you publish, changes are kept as an encrypted draft on that device.

**Timings** live at the top of `site/special/private.js` (`CFG`): prompt fade, lockout seconds, intro speed, typing speed, montage speed, folder settle time.

**What it does and does not protect.** The content, media and folder names are encrypted, and can only be unlocked with all the answers or with the editor password. Nobody can change the site without both the editor password and a GitHub token that can write to the repo. But this is a static site: the lockouts only live in the visitor's browser, and anyone can download the encrypted files and try passwords offline. An 8-digit date is a small space to guess, so treat this as a polite lock for a gift, not a vault. Do not put anything on it that would be harmful if someone got through.

## Tests

```bash
pip install playwright && playwright install chromium
cd site && python3 -m http.server 8000 &
python3 tests/audit.py http://localhost:8000/
```

Also run `python3 tests/private_flow.py` (types all three answers with short timings and walks the whole special site flow, including the Back button) and `python3 tests/private_stress.py` (phone, tablet and desktop sizes, the 10-second settle guarantee, pass-through, lockout persistence).

The audit loads every route at six screen widths and checks for console errors, failed requests, broken images, horizontal overflow, duplicate IDs, dead anchors, keyboard access, scroll restoration, and basic load metrics. It should end with `TOTAL ISSUES 0`.
